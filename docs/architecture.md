# Архитектура

## Компоненты

- `web/` — React и TypeScript. Vite собирает клиент, React Router управляет маршрутами. `src/api.ts` обрабатывает JSON, загрузки с файлами и ошибки API. Компоненты регистрации, чата, объявлений и админки отделены от каталога.
- `server/` — NestJS на Node.js. Модуль авторизации отвечает за регистрацию, вход, профиль, сессии и письма. Модуль рынка содержит каталог, объявления, чаты, отзывы, жалобы и операции администратора.
- `server/migrations/` — последовательность SQL-миграций PostgreSQL. `server/seeds/` содержит демонстрационные объявления. Основные категории, русская локаль и служебные страницы относятся к базовым данным.
- `Dockerfile` — многослойная сборка клиента и API. Контейнер запускает Node от пользователя `node`. `compose.yaml` поднимает отдельную демонстрационную БД и почтовый приёмник.

В production клиент и API обслуживаются с одного origin. В разработке Vite проксирует API в Nest. Чат запрашивает обновления по HTTP и читает историю порциями. Сообщения хранятся в PostgreSQL.

## Модель данных

| Таблицы | Назначение |
| --- | --- |
| `users`, `auth_sessions`, `email_challenges`, `auth_rate_limits` | Профили, сессии, одноразовые подтверждения и лимиты. |
| `categories`, `listings` | Иерархия категорий, объявления и настраиваемые характеристики. |
| `listing_images` | Изображения объявлений, их размеры и позиции в галерее. |
| `chats`, `chat_messages`, `chat_contact_exchanges` | Диалог по объявлению, участники, история, маркеры чтения и согласие на раскрытие контактов. |
| `reviews`, `reports` | Отзывы, рейтинги и обращения к модератору. |
| `site_locales`, `site_content` | Словари интерфейса и переводы служебных страниц. |
| `moderation_audit` | История изменений с идентификатором инициатора, причиной и состоянием сущности. |

Объявление принадлежит одному профилю и одной категории. Роль владельца задаёт направление объявления. Публичная выборка проверяет доступность объявления, профиля и ветки категорий. Поиск и фасеты выполняются параметризованными запросами в PostgreSQL. Текст и характеристики используют строковый поиск. Выборки по статусу, дате, владельцу, валюте и основным фасетам поддерживаются индексами. При росте каталога план запроса проверяется на репрезентативных данных с `EXPLAIN ANALYZE`.

Режим `ANY` у предложения продавца хранится без конкретной страны. Ранее сохранённые коды стран сохраняют прежний смысл. У предложения со складским остатком город склада остаётся отдельным полем даже при гибкой отгрузке.

Уникальные ограничения базы исключают повторные отзывы от участника в одном чате и дублирование диалога по связке объявления с инициатором. Проверка и использование одноразового кода происходят в транзакции. При запросе на раскрытие Telegram диалог запоминает версии контактов обоих участников. Подтверждение записывает факт согласия. При смене любого имени прежнее согласие перестаёт открывать контакты, а факт согласия сохраняется для разбора жалоб.

## Изображения объявлений

Сервер декодирует статические JPEG, PNG и WebP с ограничением размера файла и числа пикселей. При обработке учитывается ориентация оригинала. Изображение уменьшается до 900 пикселей по большей стороне без увеличения маленьких файлов, получает водяной знак hwforai и сохраняется как WebP без исходных метаданных.

Обработанные файлы хранятся в PostgreSQL в отдельной таблице. Общая транзакция сохраняет поля объявления и выбранный порядок файлов. Первая позиция используется как обложка. Каталог получает идентификаторы и размеры изображений, а браузер загружает сами файлы отдельными запросами. Эти запросы проходят те же проверки сессии и видимости, что и карточка объявления.

На текущем объёме PostgreSQL позволяет сохранять согласованность и включать изображения в ту же резервную копию, что и объявления. Том PostgreSQL сохраняет изображения при пересборке контейнера. При росте объёма изображений имеет смысл перенести двоичные данные в объектное хранилище, сохранив в БД размеры, порядок, связь с объявлением и правила доступа.

## Доступ и приватность

| Кто | Права |
| --- | --- |
| Гость | Категории, языки, служебные страницы и форма поиска. |
| Активный участник с подтверждённой почтой | Каталог противоположной роли, профиль, свои объявления и собственные диалоги. |
| Администратор после смены начального пароля | Редактирование профилей, объявлений, каталога, переводов и страниц. Модерация отзывов, жалоб, профилей, объявлений и просмотр аудита. |
| Интеграция с токеном | Выделенная маршрутизация модерации профилей и объявлений. |

API формирует отдельную публичную проекцию профиля. Собственный профиль содержит email и Telegram. Контакт собеседника доступен в чате только после явного согласия второй стороны. Пароли хешируются scrypt с индивидуальной солью. Код из шести цифр действует десять минут, с лимитом в пять попыток и паузой в одну минуту перед повторной отправкой. Рабочая сессия использует непрозрачный cookie `hwforai_session` сроком семь дней, `HttpOnly`, `SameSite` и `Secure` в production. В базе лежит хеш токена сессии.

Почтовый код при регистрации подтверждает адрес, при входе — доступ к почте после проверки пароля. По классификации NIST почта подходит для проверки адреса, а для защиты от фишинга нужны криптографические аутентификаторы. [NIST SP 800-63B](https://pages.nist.gov/800-63-4/sp800-63b.html), [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)

Заморозка обратима. Изменение статуса профиля отзывает открытые сессии. После восстановления участник выполняет вход снова. Постоянная блокировка исключает возобновление через обычный переход статуса. Удаление своего объявления архивирует его, сохраняя связи с историей диалогов и жалоб. Служебный токен изолирован от браузерного API администрирования. Повтор операции с тем же ключом идемпотентности обрабатывается без повторного применения действия.

## Добавление языка

1. В админке откройте раздел языков и добавьте код BCP 47, например `en`, и название языка.
2. Добавьте JSON-словарь. Ключом служит точная русская строка из вызова клиентского `t(...)`, значением — перевод. Сохраняйте маркеры вида `{count}`. При отсутствии перевода используется исходная русская строка.
3. В редакторах категорий и служебных страниц заполните переводы заголовков и описаний. Объявления и сообщения остаются в исходной формулировке участника.
4. Включите язык и проверьте навигацию, формы и отображение цен, стран и дат. Клиент запоминает выбор в браузере и обновляет атрибут `lang`.

```json
{
  "Войти": "Sign in",
  "Найдено · {count}": "Matches · {count}"
}
```

Интерфейс и редактируемый контент настраиваются через админку. Почтовые шаблоны и сообщения проверки данных хранятся в серверном коде. Для их локализации добавьте получение языка запроса и серверный словарь. Перед добавлением языков с письмом справа налево настройте `dir` и проверьте направление макета.
