# Проверка hwforai

Проверки выполняются на изолированном экземпляре с вымышленными аккаунтами и оборудованием. Интеграционные сценарии создают пользователей, объявления, чаты, отзывы и жалобы, а проверка админки меняет демонстрационные реквизиты.

## Сборка и данные

Из корня проекта соберите и запустите приложение, PostgreSQL и Mailpit. Имя проекта Compose отделяет том PostgreSQL от обычного демостенда. Токен ниже подходит только для локальной проверки.

```sh
export APP_PORT=13000 MAILPIT_UI_PORT=18025
export MODERATION_AGENT_TOKEN=local-qa-token-at-least-32-characters
docker compose -p hwforai-qa config --quiet
docker compose -p hwforai-qa up --build -d --wait
curl -fsS http://127.0.0.1:13000/api/v1/health
```

Сборка проверена на Node.js 22 и PostgreSQL 17. Контейнер отдаёт клиентскую сборку и API с одного origin. После перезапуска приложения и PostgreSQL сохранились пользователи, объявления, чаты, сообщения, журнал модерации и история миграций. Отдельный прогон подтвердил запуск нового образа на базе предыдущей сборки с сохранением данных.

## Серверные регрессии

В итоговом прогоне на чистой тестовой базе прошли все девять серверных проверок.

Сначала запустите проверку авторизации с исходным паролем демонстрационного администратора. Для проверки срока повторной отправки кода тест использует доступ к той же БД, что и приложение. Команда ниже исполняет тест внутри контейнера через стандартный ввод.

```sh
docker compose -p hwforai-qa exec -T \
  -e HWFORAI_AUTH_TEST_URL=http://127.0.0.1:3001/api/v1 \
  -e MAILPIT_URL=http://mailpit:8025 \
  app node --input-type=module < server/test/auth.integration.test.mjs
```

Проверка авторизации охватывает регистрацию компании, отказ во входе до подтверждения почты, доставку и повторную отправку кода, защиту от параллельного использования кода, блокировку после пяти ошибок, редактирование профиля, запрет прямых контактов в публичных полях и отзыв сессий при смене пароля.

```sh
HWFORAI_MARKET_TEST_URL=http://127.0.0.1:13000/api/v1 \
  MAILPIT_URL=http://127.0.0.1:18025 \
  node --test server/test/market.integration.test.mjs
```

Семь проверок каталога и модерации, включая сводный сценарий, охватывают публикацию и поиск с фильтрами, скрытие вложенных категорий, приватность профиля и ограничения по типу контрагента. Сценарии чата проверяют предупреждение о сторонних контактах, взаимное согласие и отзыв раскрытия Telegram, отзывы и жалобы. Проверки администрирования охватывают журнал аудита, повтор запросов агента и управление контентом. Для нового прогона используйте исходный демостенд или передайте актуальные реквизиты через `HWFORAI_MARKET_ADMIN_LOGIN` и `HWFORAI_MARKET_ADMIN_PASSWORD`.

Отдельная проверка на изолированной базе подтвердила, что после истечения срока карточка исчезает из каталога, новый чат по ней закрыт, а существующий чат и редактирование владельцем доступны. После обновления срока карточка снова появилась в поиске.

Отдельная проверка рабочей конфигурации использует чистую PostgreSQL и тестовый SMTP с обязательным STARTTLS. Сценарий проверяет отказ для демовхода и запроса с постороннего origin, доставку кода первичному администратору и флаги сессионного cookie. Затем тест меняет логин и пароль администратора, проверяет отзыв старой сессии и входит с новыми реквизитами и новым кодом из письма. Для каждого прогона используйте экземпляр с `NODE_ENV=production`, доступным тестовым почтовым ящиком и новым первичным администратором. Передайте тесту те же `APP_ORIGIN` и `BOOTSTRAP_ADMIN_USERNAME`, `BOOTSTRAP_ADMIN_EMAIL`, `BOOTSTRAP_ADMIN_PASSWORD`, а также адреса приложения и Mailpit. [Настройка рабочей конфигурации](operations.md)

```sh
HWFORAI_PRODUCTION_TEST_URL=http://127.0.0.1:13001/api/v1 \
  MAILPIT_URL=http://127.0.0.1:18026 \
  node --test server/test/production.integration.test.mjs
```

## Браузерные сценарии

Установите Playwright в отдельное Python-окружение и укажите путь к Chromium, установленному в вашей системе.

```sh
python -m pip install playwright
export CHROMIUM_PATH=/usr/bin/chromium
export HWFORAI_TEST_CHROMIUM="$CHROMIUM_PATH"
```

```sh
HWFORAI_URL=http://127.0.0.1:13000 python tests/catalog_ui.py
HWFORAI_QA_BASE=http://127.0.0.1:13000 HWFORAI_QA_MAILPIT_URL=http://127.0.0.1:18025 \
  python tests/account_listing_e2e.py
HWFORAI_TEST_URL=http://127.0.0.1:13000 python tests/chat_e2e.py
```

Браузерные сценарии прошли в Chromium на ширинах от 320 до 1440 пикселей, с клавиатуры и в мобильном режиме. Сценарии проверяют видимость карточек для гостя и участников, возврат к поиску после входа, регистрацию и получение кода через Mailpit, профиль, смену пароля, обе формы объявлений и двусторонний чат.

Для браузерной проверки админки поднимите отдельный экземпляр Compose с исходными реквизитами администратора.

```sh
HWFORAI_ADMIN_QA_URL=http://127.0.0.1:13002 HWFORAI_QA_CHROMIUM="$CHROMIUM_PATH" \
  python tests/admin_e2e.py
```

Сценарий охватывает вход и смену начальных реквизитов, модерацию профилей и объявлений, управление категориями, доказательствами по жалобе, отзывами, страницами и языками. Прошли все 13 сценариев админки, включая журнал действий и переключение языка на ширине 320 пикселей.

Дополнительно проверены совместная работа фильтров оплаты, НДС, цены и доставки, сохранение фильтров при перезагрузке страницы и сброс настроек. На главной странице, входе, регистрации, в профиле, редакторе и списке объявлений, чатах и на экране пользователей админки прошли все 16 проверок axe-core по правилам WCAG 2 и 2.1 уровней A и AA на ширинах 320 и 1440 пикселей. На этих страницах в проверенных состояниях не было горизонтального переполнения. HTML, JS и CSS итогового контейнера совпали с файлами протестированной браузерной сборки.

Рабочую доставку по SMTP внешнего провайдера и публичное HTTPS-развёртывание нужно проверить с параметрами выбранного хостинга. Тестовая доставка выполнена через локальный Mailpit.
