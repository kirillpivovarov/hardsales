# Эксплуатация

## Локальная разработка

Требуются Node.js 22.12 или новее, npm и PostgreSQL 17. Демостенд в корневом `compose.yaml` поднимает все сервисы вместе. Для разработки с Vite можно запустить PostgreSQL отдельно и читать одноразовые коды в журнале API.

Если у вас ещё нет локальной БД, запустите тестовую PostgreSQL в Docker. Команда открывает её только на вашем компьютере. Контейнер и его тестовая БД удаляются при остановке.

```sh
docker run --rm -d --name hwforai-dev-db -p 127.0.0.1:5433:5432 \
  -e POSTGRES_USER=hwforai -e POSTGRES_PASSWORD=hwforai -e POSTGRES_DB=hwforai \
  postgres:17-bookworm
docker exec hwforai-dev-db pg_isready -h 127.0.0.1 -U hwforai -d hwforai
```

Дождитесь сообщения `accepting connections`. Для уже запущенной базы используйте свой адрес в `DATABASE_URL`.

Установите зависимости из корня репозитория.

```sh
npm --prefix server ci
npm --prefix web ci
```

Запустите сервер из каталога `server`.

```sh
cd server
export DATABASE_URL=postgresql://hwforai:hwforai@127.0.0.1:5433/hwforai
export DEMO_MODE=true
export MAIL_TRANSPORT=console
npm run build
npm start
```

Запустите клиент из корня проекта в отдельном терминале.

```sh
npm --prefix web run dev
```

Vite выводит адрес клиента в терминал. По умолчанию он открывается на `http://127.0.0.1:5173` и проксирует `/api` на `http://127.0.0.1:3001`. Для нестандартного адреса API задайте `API_PROXY_TARGET` перед запуском Vite. В режиме `MAIL_TRANSPORT=console` код появляется в журнале API. Для проверки SMTP-доставки выберите режим `smtp`, укажите параметры SMTP Mailpit и откройте его почтовый ящик.

```sh
npm --prefix server run check
npm --prefix web run typecheck
npm --prefix server run build
npm --prefix web run build
```

Для проверки авторизации на отдельном демостенде с Mailpit выполните `npm --prefix server run test:auth`. Укажите `HWFORAI_AUTH_TEST_URL` с префиксом API, `MAILPIT_URL` с API тестовой почты и `DATABASE_URL` той же тестовой БД. Проверке нужен администратор с исходными демонстрационными реквизитами.

Интеграционная проверка рынка меняет демонстрационные данные, включая реквизиты администратора, и выполняется на отдельном стенде. Передайте `HWFORAI_MARKET_TEST_URL` с префиксом API, `MAILPIT_URL` и тот же `MODERATION_AGENT_TOKEN`, что настроен у тестового сервера. При повторном прогоне задайте текущий пароль через `HWFORAI_MARKET_ADMIN_PASSWORD`. Логин можно задать через `HWFORAI_MARKET_ADMIN_LOGIN`.

```sh
node --test server/test/market.integration.test.mjs
```

Сервер применяет миграции до открытия порта. URL проверки готовности — `GET /api/v1/health`. Возвращает `{"status":"ok"}` при доступной базе.

## Рабочая конфигурация

Для развёртывания нужны Docker-хост, PostgreSQL, SMTP и домен с HTTPS. Корневой `compose.yaml` предназначен для локальной проверки с демонстрационными аккаунтами. Публикация репозитория на GitHub даёт доступ к исходникам и командам запуска.

Соберите образ из корня проекта и передайте конфигурацию при запуске контейнера.

```sh
docker build -t hwforai:0.1.0 .
```

Используйте `.env.example` как список параметров для менеджера секретов хостинга. Если запускаете Docker напрямую, пример команды с подготовленным приватным файлом окружения выглядит так.

```sh
docker run -d --name hwforai --restart unless-stopped \
  --env-file /path/to/private/hwforai.env -p 127.0.0.1:3001:3001 hwforai:0.1.0
```

В образе Node обслуживает REST API и сборку React на одном origin. Проксируйте через HTTPS на порт приложения `3001`. Сохраняйте исходный `Origin` в HTTP-запросах. При проксировании задайте точное число доверенных переходов в `TRUST_PROXY_HOPS` и ограничьте доступ к внутреннему порту сетью прокси. Для PostgreSQL используйте отдельную базу, закрытую сеть, TLS с проверкой сертификата и постоянное хранилище. Для рабочего запуска нужна база без демонстрационных аккаунтов.

| Параметр | Значение |
| --- | --- |
| `NODE_ENV`, `DEMO_MODE` | На рабочем стенде `production` и `false`. |
| `PORT` | Внутренний порт HTTP, по умолчанию `3001`. |
| `DATABASE_URL` | Строка подключения PostgreSQL для выделенной базы. |
| `APP_ORIGIN` | Публичный HTTPS origin без пути или query, например `https://hwforai.example.org`. |
| `TRUST_PROXY_HOPS` | Число доверенных обратных прокси между клиентом и приложением для определения IP, от 0 до 5. |
| `SERVE_WEB_DIR` | Абсолютный путь к клиентской сборке. Образ задаёт `/app/web`. |
| `OTP_SECRET` | Случайное значение длиной минимум 32 символа. Для всех экземпляров с общей БД используйте одно значение. |
| `MAIL_TRANSPORT` | `smtp` для рабочего стенда, `console` для локальной разработки. |
| `SMTP_HOST`, `SMTP_PORT` | Хост и порт почтового провайдера. |
| `SMTP_SECURE`, `SMTP_REQUIRE_TLS` | Настройка режима TLS в соответствии с портом. |
| `SMTP_USER`, `SMTP_PASS` | Учётные данные сервиса отправки. |
| `MAIL_FROM` | Имя и адрес отправителя с локальной частью `no-reply` на подтверждённом домене. |
| `BOOTSTRAP_ADMIN_USERNAME`, `BOOTSTRAP_ADMIN_EMAIL`, `BOOTSTRAP_ADMIN_PASSWORD` | Первичная инициализация на пустой базе. |
| `MODERATION_AGENT_TOKEN` | Секрет для выделенного API модерации. Пустое значение отключает доступ по токену. |

Сгенерируйте секрет следующей командой.

```sh
node -e "process.stdout.write(require('node:crypto').randomBytes(32).toString('hex'))"
```

Для первого администратора задайте отдельный логин, доступный почтовый адрес и пароль длиной минимум 12 символов. После запуска получите код на эту почту и завершите обязательную смену реквизитов в настройках. Затем уберите пароль и прочие параметры первоначальной настройки из окружения. Повторный запуск читает данные существующего администратора из БД.

## Почта

Подключите SMTP провайдера хостинга или сервис транзакционных писем. Провайдер должен разрешать отправку с `no-reply@ваш-домен`. Для порта 465 обычно требуется `SMTP_SECURE=true`. Для порта 587 с обязательным STARTTLS задайте `SMTP_SECURE=false` и `SMTP_REQUIRE_TLS=true`. Укажите DNS-записи SPF, DKIM и DMARC по инструкции провайдера. Проверьте доставку к нескольким реальным почтовым сервисам и проверьте заголовки аутентификации перед открытием регистрации. [Nodemailer SMTP](https://nodemailer.com/smtp), [Google Email Sender Guidelines](https://support.google.com/mail/answer/81126?hl=en)

На демостенде Mailpit принимает письма по SMTP и отображает их в браузере. Для проверки сбоев доставки смотрите журнал приложения и состояние хоста SMTP. [Документация Mailpit](https://mailpit.axllent.org/docs/install/docker/)

## Обновления и данные

Добавляйте SQL-миграции с очередным уникальным номером в `server/migrations/`. Зафиксированные миграции содержат контрольные суммы. Изменения существующей схемы оформляйте новой миграцией. Сначала примените обновление на копии данных, затем разворачивайте его с пригодной для восстановления резервной копией.

Резервная копия содержит персональные данные и переписку. Ограничьте доступ, включите шифрование хранилища и проверяйте восстановление в изолированную среду.

```sh
pg_dump --format=custom --file=hwforai.backup "$DATABASE_URL"
pg_restore --exit-on-error --no-owner --dbname="$RECOVERY_DATABASE_URL" hwforai.backup
```

Проверяйте доступность `/api/v1/health`, ошибки SMTP, долю успешных подтверждений, размер базы и задержки каталога. Для рабочей среды задайте сроки хранения переписки, жалоб и аудита в соответствии с опубликованной политикой. Сервер периодически очищает просроченные сессии, одноразовые вызовы и счётчики ограничений.
