# hwforai · закрытая биржа

Русскоязычная площадка объявлений о покупке и продаже серверного оборудования для ИИ. Покупатели публикуют запросы, продавцы размещают предложения. Участники находят оборудование по моделям, характеристикам и коммерческим условиям. Переговоры начинаются в чате объявления. Ветка `maxv` добавляет приглашения, контроль актуальности, представительство, автоматические совпадения, справочник моделей и проверку сделок.

## Локальный запуск

Запустите Docker Desktop или Docker Engine с Compose. Для `maxv` используйте отдельный клон.

```sh
git clone --branch maxv --single-branch https://github.com/kirillpivovarov/hardsales.git "$HOME/hardsales-maxv"
cd "$HOME/hardsales-maxv"
EXCHANGE_DEMO_FEATURES=true sh scripts/update-maxv.sh
```

- [Площадка](http://127.0.0.1:3100)
- [Тестовая почта в Mailpit](http://127.0.0.1:8125)

| Сценарий | Логин | Пароль | Вход |
| --- | --- | --- | --- |
| Прямой продавец | `test1` | `test1` | Сразу |
| Покупатель | `test2` | `test2` | Сразу |
| Продавец в режиме агента | `testagent` | `Agent-Maxv-2026!` | Код в Mailpit для `testagent@example.test` |
| Модератор | `testmod` | `Moderator-Maxv-2026!` | Код в Mailpit для `testmod@example.test` |
| Администратор | `admin` | `admin` | При первом входе смените пароль |

Для регистрации нового покупателя используйте приглашение `K7PQ-M2XA`, для продавца — `H3BC-X5LM`. Приглашения одноразовые. Новые коды создаёт администратор в **«Закрытая биржа → Приглашения»**.

`EXCHANGE_DEMO_FEATURES=true` один раз добавляет примеры и включает функциональность биржи в базе Compose. Запланированную синхронизацию каталога включают отдельно. Без этой переменной доступны базовые аккаунты и открытая регистрация. Порты задаются через `APP_PORT` и `MAILPIT_UI_PORT`. Адреса слушают локальный интерфейс.

```sh
docker compose ps
docker compose logs --tail 100 app
```

Для остановки выполните `docker compose down`. Данные хранятся в томе `hwforai-maxv_postgres-data`.

## Обновление Docker Desktop на macOS

При запущенном Docker Desktop выполните в Terminal.

```sh
cd "$HOME/hardsales-maxv" &&
test "$(git branch --show-current)" = maxv &&
git pull --ff-only origin maxv &&
EXCHANGE_DEMO_FEATURES=true sh scripts/update-maxv.sh
```

Скрипт проверяет текущую ветку, адрес репозитория и отсутствие локальных правок в отслеживаемых файлах, сверяет коммит с GitHub и обновляет проект `hwforai-maxv`. Compose применяет миграции к существующему тому этого проекта. Сохраняйте файл `.env` и собственные значения портов. Для обновления с возможностью отката [сделайте резервную копию](#резервная-копия-и-восстановление).

Ветка и Docker-проект изолированы. Экземпляр из основной ветки можно оставить запущенным на его обычных портах. При установке из ZIP выберите архив ветки `maxv`, перейдите в распакованную папку и выполните `EXCHANGE_DEMO_FEATURES=true docker compose -p hwforai-maxv up --build -d --wait`. Безвозвратное удаление локальной базы выполняется отдельной командой `docker compose -p hwforai-maxv down -v`.

### Резервная копия и восстановление

Из папки с текущим `compose.yaml` выполните команды. Подставьте своё имя проекта, если оно отличается от `hwforai-maxv`. Копия появится рядом с папкой проекта. В ней содержатся объявления, фотографии, переписка и данные пользователей.

```sh
backup="hwforai-before-$(date +%Y%m%d-%H%M%S).dump"
docker compose -p hwforai-maxv exec -T postgres pg_dump -U hwforai -d hwforai --format=custom --file="/tmp/$backup" &&
docker compose -p hwforai-maxv exec -T postgres pg_restore --list "/tmp/$backup" &&
docker compose -p hwforai-maxv cp "postgres:/tmp/$backup" "../$backup" &&
chmod 600 "../$backup"
```

Для проверки отката откройте исходники предыдущей версии в отдельной папке и восстановите копию в чистую базу отдельного проекта. Выберите свободные `APP_PORT` и `MAILPIT_UI_PORT` перед запуском восстановленного приложения рядом с текущим.

```sh
docker compose -p hwforai-recovery up -d --wait postgres
docker compose -p hwforai-recovery cp /path/to/backup.dump postgres:/tmp/backup.dump
docker compose -p hwforai-recovery exec -T postgres pg_restore -U hwforai -d hwforai --exit-on-error --no-owner /tmp/backup.dump
```

Для базы вне Compose используйте `pg_dump --format=custom --file=hwforai.backup "$DATABASE_URL"` и проверяйте восстановление в отдельную базу командой `pg_restore --exit-on-error --no-owner --dbname="$RECOVERY_DATABASE_URL" hwforai.backup`. Ограничьте доступ к резервным копиям и шифруйте хранилище.

## Работа с площадкой

1. Откройте каталог как гость. Категории и поиск видны сразу. Карточки и данные авторов доступны после входа.
2. Пройдите регистрацию с приглашением, локальной CAPTCHA и кодом из Mailpit. Заполните короткую анкету и примите действующую редакцию правил перед публикацией или перепиской.
3. Войдите как продавец `test1` и разместите предложение. В отдельном окне войдите как покупатель `test2`, разместите заявку на ту же модель и проверьте **«Совпадения»**. Проверка учитывает количество, состояние, доставку, цену, представительство и условия оплаты.
4. Начните переговоры в чате. После двустороннего согласия контакт доступен в других активных диалогах с тем же собеседником. Откройте **«Раскрытия»** для просмотра истории и **«Сделки»** для фиксации результата переговоров.
5. Войдите как `testagent`. В **«Профиле»** добавьте принципала, настройте вознаграждение и откройте форму подтверждения через письмо или запрос участнику. В каталоге видны режим и признаки подтверждения.
6. Войдите как администратор или модератор. Контекстные действия находятся на самих карточках и страницах. Очереди предложений моделей, раскрытий, принципалов, проверок и совпадений находятся в разделе **«Закрытая биржа»**.

### Правила биржи

**Доступ и публикация.** Приглашение передаёт сотрудник вручную. При отправке формы код ещё свободен. Сервер закрепляет его только после успешной проверки почты в той же транзакции, что и создание аккаунта. Приглашение может закреплять покупателя или продавца. Анкета обязательна для новых участников закрытой регистрации. У ранее зарегистрированных анкета добровольна, действующая версия правил обязательна при следующей публикации. Доступ к ответам есть у владельца и администратора.

**Актуальность.** «Мои объявления» разделяет текущие публикации, архив и ограничения. Система отправляет ежедневный запрос после 10:00 и напоминание после 16:00 по времени площадки. Через 24 часа без ответа объявление скрывается. Его можно вернуть в течение семи дней. После трёх пропущенных дней требуется восстановить готовность отвечать. В профиле доступна пауза до пяти дней в месяц. Временное скрытие при проверке снимает сотрудник. Срок поставки по календарной дате считается по UTC.

**Раскрытие и агент.** До согласия виден псевдоним, а публичные карточки показывают статус представительства без имени принципала. При раскрытии сохраняется снимок реквизитов и версии правил. Смена Telegram отзывает доступ к старым реквизитам и запускает новый обмен. История доступна сторонам с учётом действующей приватности и сотрудникам с аудитом доступа. Режим агента — настройка покупателя или продавца. Он выбирает принципала при публикации, а сам принципал подтверждает сведения через защищённую ссылку или из своего профиля. Вознаграждение раскрывается в заданном участником объёме.

**Справочник и совпадения.** Модель можно выбрать из справочника или описать свободным текстом. Поиск по модели учитывает альтернативные написания, подбор по заявке учитывает выбранные аналоги. Автоматические совпадения формируются для объявлений с моделью. Из совпадения можно перейти в чат. Администратор видит очередь с причинами и ведёт курсы валют и источники синхронизации. Отсутствующий курс исключает автоматическое сравнение цены в разных валютах.

**Проверки и оплата.** Документы проверки видны владельцу и сотрудникам с соответствующими полномочиями. Частные файлы хранятся отдельно от фотографий объявления. Лимит активных объявлений зависит от уровня проверки: 3, 15 или без ограничения. Рейтинг учитывает подтверждения, дисциплину, сделки и решения по жалобам. В обычном каталоге результаты ниже заданного порога доступны через **«Показать все объявления, включая низкий рейтинг»**. Справочник оплаты показывает условия и риски. Сайт ведёт статус переговоров и сделки, расчёты проводят сами стороны.

### Профили, каталог и поиск

При регистрации указываются логин, email, пароль, страна, город, имя пользователя Telegram, роль и тип участника. Для компании требуется название. Аккаунт создаётся после ввода кода из письма. Email и логин уникальны без учёта регистра. Публичный ник, название компании и имя Telegram могут совпадать у разных пользователей. Telegram указывается самим участником. Площадка проверяет доступ к почте при регистрации. [Проверка email по OWASP](https://cheatsheetseries.owasp.org/cheatsheets/Email_Validation_and_Verification_Cheat_Sheet.html)

Публичный профиль содержит ник, тип участника, город, страну и репутацию. Покупатель видит предложения продавцов, продавец видит заявки покупателей. Собственные объявления доступны отдельно. Перед запросом письма регистрации пройдите проверку браузера ALTCHA. В локальном демостенде письмо приходит в Mailpit.

Поиск учитывает заголовок, описание, категорию, названия и значения характеристик и город. Например, варианты `NVIDIA H100 80GB`, `НВИДИА Н-100 80 ГБ` и `H 100 SXM` могут найти одну и ту же модель при совпадающих характеристиках. Учитываются известные варианты написания брендов, разделители, единицы измерения и небольшие опечатки. Так, `1,92 ТБ` и `1.920TB` дают одинаковое значение для поиска. Номер модели помогает отличить близкие товары, например H100 и H200. При текстовом запросе сначала показываются более точные совпадения. Сортировку по дате и цене можно выбрать явно.

Фасеты по географии, цене, валюте, типу контрагента, наличию, состоянию, оплате и НДС применяются одновременно с текстом. Из карточки можно вернуться к прежней выдаче. Общие фильтры и параметры конкретных категорий хранятся отдельно. [Каталоги NVIDIA](https://www.nvidia.com/en-us/data-center/products/), [Supermicro](https://www.supermicro.com/en/products/gpu), [Фасеты Algolia](https://www.algolia.com/doc/guides/managing-results/refine-results/faceting)

| Категория | Примеры характеристик |
| --- | --- |
| GPU и ускорители | Модель, видеопамять, SXM или PCIe. |
| GPU-серверы и узлы | Количество ускорителей, процессор, память, состав платформы. |
| Серверные процессоры | Сокет, число ядер, теплопакет. |
| Серверная память | Тип ECC RDIMM или LRDIMM, ёмкость, скорость. |

| Стойки и корпуса | Высота в U, ширина, глубина и нагрузка. |

### Страны и условия сделки

Сначала в списках стран идут Россия, Казахстан, Кыргызстан и Узбекистан. Следом идут в алфавитном порядке на языке интерфейса Азербайджан, Армения, Беларусь, Молдова, Таджикистан и Туркменистан. После них идут ОАЭ и Китай, затем остальные страны по алфавиту. Список открывается с верхней части, сохраняя выбранное значение, в браузерах с поддержкой Popover. Системный список в более ранних браузерах сохраняет порядок стран. В полях, где предусмотрены варианты «Любая страна» и «Без ограничения», они доступны отдельно от стран.

Покупатель указывает крайний срок, страну получения и допустимый источник. Продавец указывает наличие, страну отгрузки или гибкую географию. Для товара на складе город указывается отдельно. Продавец может также указать, до какого дня его предложение действительно. Фильтр по конкретной стране отгрузки включает объявления с гибкой географией. Фильтр по стране получения сохраняет предложения, у которых страна обсуждается. Фактический маршрут стороны уточняют в чате.

Цена закупки означает верхний предел, цена продавца — заявленную стоимость. Договорные цены и валюты хранятся со значениями, которые выбрали участники. Доставка, оформление, пошлины, НДС, способ оплаты и допустимый тип контрагента отображаются отдельно. Для трансграничной сделки стороны проверяют требования к товару, получателю, конечному использованию, документам и лицензиям. [Правила продавцов eBay](https://www.ebay.com/help/policies/selling-policies/selling-practices-policy?id=4346), [ICC Incoterms](https://library.iccwbo.org/clp/clp-incoterms.htm?AGENT=ICC_FIN), [BIS Russia and Belarus Country Guidance](https://www.bis.gov/licensing/country-guidance/russia-belarus)

### Фотографии

К объявлению можно добавить до десяти статических JPEG, PNG или WebP, каждый размером до 8 МиБ и 25 мегапикселей. Первая фотография становится обложкой. Порядок, состав и обложку можно менять при редактировании. Администратор и модератор могут редактировать фотографии прямо из карточки объявления.

При загрузке сервер учитывает ориентацию оригинала, уменьшает длинную сторону до 900 пикселей, наносит полупрозрачный водяной знак hwforai и сохраняет WebP без исходных метаданных. Небольшие кадры сохраняют свой размер. Уже сохранённые WebP содержат знак, нанесённый при загрузке. Для нового оформления замените снимок файлом оригинала.

### Чаты и отзывы

Любой собеседник может запросить раскрытие Telegram. После согласия второй стороны имена и ссылки доступны в существующих и новых активных диалогах этой пары, в том числе по объявлениям другой стороны. При смене имени Telegram одним из участников чат убирает ссылки у обоих, показывает уведомление и предлагает обменяться заново. Возврат к прежнему имени также требует нового согласия. Имена сравниваются без учёта регистра, как в Telegram. История реальных изменений хранится в PostgreSQL. Собеседнику доступны только имена из действующего обмена. [Справка Telegram об именах пользователей](https://telegram.org/faq#q-what-can-i-use-as-my-username)

При обнаружении стороннего контакта чат показывает правила рассмотрения жалоб. Жалобу можно подать на диалог на площадке или на ранее раскрытый в системе Telegram. Начинайте переговоры в чате, чтобы при необходимости администратор или модератор мог открыть переписку по жалобе. Открытие переписки фиксируется в журнале. [Политика eBay об общении участников](https://www.ebay.com/help/policies/member-behavior-policies/membertomember-contact-policy?id=4262)

После обмена сообщениями участник может оставить по одному отзыву на диалог. Публичные отзывы и рейтинг по делам отображаются отдельно. При расчёте публичного рейтинга учитывается последняя видимая оценка от каждого собеседника. Администратор и модератор могут скрыть отзыв и разобрать жалобу. Архивирование своего объявления сохраняет историю общения и жалоб. [Расчёт повторных оценок у eBay](https://www.ebay.com/help/default/default/leaving-feedback-sellers?id=4007)

### Модерация на страницах площадки

Администратору и модератору доступны действия рядом с объявлением, его автором, категорией и информационной страницей. Из профиля автора можно открыть отзывы и жалобы о нём. Редактор текущего языка доступен внизу страницы. После сохранения изменения отображаются на текущей странице. В разделе администрирования доступны сводные списки и журнал. При смене статуса нужно указать причину. Заморозка обратима, бессрочная блокировка требует отдельного подтверждения. [Редактирование объекта в WordPress](https://developer.wordpress.org/reference/functions/edit_post_link/), [подтверждение действий в GOV.UK Design System](https://design-system.service.gov.uk/components/button/), [журнал модерации Reddit](https://support.reddithelp.com/hc/en-us/articles/15484543117460-Moderation-Log)

| Действие | Администратор | Модератор |
| --- | --- | --- |
| Редактировать объявления, профили участников рынка, категории, страницы и локали | Да | Да |
| Модерировать объявления, профили участников рынка, отзывы и жалобы | Да | Да |
| Просматривать журнал и переписку по поданной на площадке жалобе | Да | Да |
| Создавать, замораживать, размораживать и бессрочно блокировать модераторов | Да | — |

В разделе **«Модераторы»** администратор задаёт логин, имя, почту и временный пароль. Модератор входит по этим реквизитам, подтверждает почту кодом и меняет временный пароль. Заморозка и блокировка отзывают действующие сессии и неиспользованные коды входа. При разморозке нужно войти снова. На площадке предусмотрен один администратор.

Поисковые запросы параметризованы и выполняются в PostgreSQL. Публичная выборка проверяет доступность объявления, профиля и всей ветки категорий. После истечения срока по UTC объявление исчезает из поиска. Автор сохраняет доступ к карточке, а собеседники к существующему диалогу. Для повторной публикации укажите актуальный срок.

Миграция добавляет общую нормализацию запроса и данных. Поисковые слова хранятся в вычисляемых столбцах объявлений, категорий и профилей. Индексы GIN помогают сузить поиск, затем сервер проверяет каждое слово и оценивает совпадения в заголовке выше совпадений в характеристиках. В латинских словах длиной от пяти букв после нормализации допускается одна вставка, удаление, замена или перестановка соседних символов. Цифровые части модели и суффиксы сохраняются. Изменения словаря оформляйте новой миграцией с пересчётом поисковых столбцов и зависимых индексов. [Миграция поисковых данных](server/migrations/005_catalog_search.sql)

Сервер обрабатывает поля объявления и порядок фото в одной транзакции. Каталог возвращает URL, размеры и идентификаторы фото, а браузер загружает файлы отдельно. Для чтения обработанного файла применяются права доступа к карточке. Фотографии входят в резервную копию PostgreSQL. Чат получает обновления по HTTP и читает историю порциями. Согласие относится к двум идентификаторам пользователей и версиям их Telegram. Ответ содержит идентификатор запроса, чтобы уже открытая вкладка не могла подтвердить более позднее предложение. При обновлении базы сервер переносит подтверждённые обмены с действующими именами и сохраняет известные сведения об истории обменов. Накопление истории изменений самого имени начинается с установки этой версии.

Пароли хешируются scrypt с индивидуальной солью. Одноразовый почтовый код действует десять минут и ограничен пятью попытками. Повторная отправка доступна через минуту и отменяет предыдущий код. Для одного адреса доступны до пяти кодов регистрации и до шести кодов входа в час с учётом повторных отправок. Запросы также ограничены по IP. Сессия использует cookie `hwforai_session` сроком семь дней с `HttpOnly` и `SameSite`. В production добавляется `Secure`. Токен сессии хранится в виде хеша. Проверка кода выполняется в транзакции. [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html), [OWASP Authentication](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)

Миграции `010`–`018` разделены по подсистемам. Планировщик использует блокировки PostgreSQL и уникальные слоты, чтобы два экземпляра не выполнили одну работу одновременно. Почтовая очередь фиксируется вместе с бизнес-действием и повторяет отправку отдельно. Одноразовые ссылки хранятся как хеши. Открытие ссылки показывает форму, действие выполняется после подтверждения. Telegram-бот в этот релиз не входит.

Справочник содержит исходные связи моделей, псевдонимы и группы аналогов. Для сетевого импорта используются разрешённые HTTPS-источники с ограничением в 5 МиБ и учётом ETag. Найденные синонимы, новые записи и сигналы со страниц производителей проверяет сотрудник. Коды и названия ускорителей частично получены из базы PCI ID с лицензией GPL-2.0-or-later или BSD-3-Clause. [PCI ID Repository](https://pci-ids.ucw.cz/) · [NVIDIA Data Center GPU](https://www.nvidia.com/en-us/data-center/)

В админке добавьте код BCP 47, например `en`, название и JSON-словарь. Ключом служит точная русская строка из клиентского вызова `t(...)`. Сохраняйте маркеры вида `{count}`. Для отсутствующего перевода используется исходная строка.

```json
  "Найдено · {count}": "Matches · {count}"
}
```

В редакторах категорий и страниц заполните переводы заголовков и описаний. Объявления и сообщения отображаются в исходной формулировке. Клиент сохраняет выбор языка в браузере и обновляет `lang`. Почтовые шаблоны и тексты серверной валидации находятся в серверном коде. Визуальная система использует Manrope и IBM Plex Mono с локальными лицензиями. [Референс оформления](https://github.com/kirillpivovarov/lev)

## Локальная разработка

Требуются Node.js 22.12 или новее, npm и PostgreSQL 17 с кодировкой UTF-8. Используйте отдельную тестовую базу. Например, временную копию PostgreSQL можно запустить на порту 5433.

```sh
docker run --rm -d --name hwforai-dev-db -p 127.0.0.1:5433:5432 \
  -e POSTGRES_USER=hwforai -e POSTGRES_PASSWORD=hwforai -e POSTGRES_DB=hwforai postgres:17-bookworm
docker exec hwforai-dev-db pg_isready -h 127.0.0.1 -U hwforai -d hwforai
npm --prefix server ci
npm --prefix web ci
```

Дождитесь `accepting connections` и запустите API в одном терминале.

```sh
cd server
export NODE_ENV=development
export DATABASE_URL=postgresql://hwforai:hwforai@127.0.0.1:5433/hwforai
export DEMO_MODE=true
export MAIL_TRANSPORT=console
npm run build
npm start
```

В другом терминале из корня проекта выполните `npm --prefix web run dev`. По умолчанию Vite открывается на порту 5173 и проксирует `/api` на порт 3001. Для другого адреса API установите `API_PROXY_TARGET`. В режиме `MAIL_TRANSPORT=console` коды появляются в журнале API. Для тестов доставки используйте Mailpit.

Запускайте `npm run check` для TypeScript и `npm run build` для сборки из корня. Новые изменения схемы добавляйте отдельным SQL-файлом с очередным номером. Сервер применяет миграции до открытия HTTP-порта. При доступной БД `GET /api/v1/health` возвращает `{"status":"ok"}`.

## Рабочее развёртывание

Для публичного сайта нужны Docker-хост, выделенная PostgreSQL, SMTP и домен с HTTPS. Корневой `compose.yaml` предназначен для локального демостенда. Подготовьте рабочую базу и приватный файл параметров по образцу [.env.example](.env.example).

```sh
docker build -t hwforai:local .
docker run -d --name hwforai --restart unless-stopped \
  --env-file /path/to/private/hwforai.env -p 127.0.0.1:3001:3001 hwforai:local
```

Проксируйте HTTPS на порт 3001, сохраняйте исходный заголовок `Origin` и настройте подключение к PostgreSQL с проверкой TLS. Для маршрутов загрузки фотографий выставьте лимит тела запроса на прокси 81 МиБ. Для ограничения объёмного трафика настройте защиту от DDoS на хостинге или внешнем прокси. Приложение ограничивает частоту запросов к авторизации и проверяет CAPTCHA на регистрации. [OWASP Bot Management](https://cheatsheetseries.owasp.org/cheatsheets/Bot_Management_and_Anti-Automation_Cheat_Sheet.html)

| Параметры | Значение |
| --- | --- |
| `NODE_ENV`, `DEMO_MODE` | `production` и `false`. |
| `DATABASE_URL` | Подключение к выделенной базе. |
| `APP_ORIGIN` | Публичный HTTPS origin без пути, например `https://hwforai.example.org`. |
| `PORT`, `SERVE_WEB_DIR` | HTTP-порт и абсолютный путь к клиенту. В образе это 3001 и `/app/web`. |
| `TRUST_PROXY_HOPS` | Точное число доверенных обратных прокси, от 0 до 5. |
| `OTP_SECRET` | Случайное значение длиной от 32 символов, одинаковое на экземплярах с общей БД. |
| `MAIL_TRANSPORT`, `SMTP_HOST`, `SMTP_PORT` | `smtp`, хост и порт почтового провайдера. |
| `SMTP_SECURE`, `SMTP_REQUIRE_TLS`, `SMTP_USER`, `SMTP_PASS` | Режим соединения и данные SMTP. |

| `MODERATION_AGENT_TOKEN` | Необязательный секрет выделенного API модерации. |

Проверка ALTCHA работает на домене площадки. Сервер создаёт и подписывает задачу на пять минут, браузер вычисляет решение, а сервер проверяет его и помечает задачу использованной. Клиентский код поставляется со сборкой. Браузеру нужен защищённый контекст, например HTTPS или локальный `127.0.0.1`. Секрет подписи выводится из `OTP_SECRET`. Установка демостенда и рабочего сайта обходится без отдельной учётной записи CAPTCHA, CDN и внешнего API проверки. Для каждого IP доступны до 40 задач за 15 минут и до 12 попыток отправить форму регистрации в час. [ALTCHA Server Integration](https://altcha.org/docs/integration/server/), [ALTCHA для Node.js](https://github.com/altcha-org/altcha-lib)

На рабочую базу приходится одна активная учётная запись администратора с подтверждённой почтой. Публичная регистрация доступна покупателям и продавцам. Создайте начальный пароль администратора, например командой `openssl rand -hex 32`. Войдите с паролем и кодом из почты и выполните обязательную смену реквизитов. Изменить логин и пароль администратора может он сам из своей сессии с действующим паролем. Смена отзывает прежние сессии и коды входа и фиксируется в журнале без сохранения секрета. После инициализации уберите из окружения пароль и другие параметры первоначальной настройки. Для модераторов используйте персональные адреса и передавайте временные пароли защищённым способом. API агента модерации работает с профилями покупателей и продавцов и объявлениями.

Для SMTP на порту 465 обычно используется `SMTP_SECURE=true`. Для порта 587 с обязательным STARTTLS используйте `SMTP_SECURE=false` и `SMTP_REQUIRE_TLS=true`. Настройте SPF, DKIM и DMARC у провайдера и проверьте внешнюю доставку. Наблюдайте за `/api/v1/health`, задержками каталога, ошибками SMTP, размером базы и резервным копированием. [Nodemailer SMTP](https://nodemailer.com/smtp), [Рекомендации к отправителям Google](https://support.google.com/mail/answer/81126?hl=en)

## HTTP API

Пути в таблицах указаны относительно `/api/v1`. Защищённые маршруты используют cookie `hwforai_session`. Тела по умолчанию принимаются как `application/json`. Ошибка возвращает HTTP-статус и `message` строкой или массивом строк. Основные статусы включают `401` для отсутствующей сессии, `403` для недостатка прав, `404` для недоступной сущности, `409` для конфликта и `429` для ограничения частоты.

### Авторизация

| Метод и путь | Запрос и ответ |
| --- | --- |
| `GET /auth/captcha` | Подписанная задача ALTCHA для регистрации. |
| `POST /auth/register` | `username`, `email`, `password`, `role`, `participantType`, `country`, `city`, `telegram`, `captchaToken`, а для компании также `companyName`. |
| `POST /auth/login` | `login` и `password`. Возвращает вызов подтверждения или `{user}` для готового демоаккаунта. |
| `POST /auth/verify` | `{challengeId, code}`. Устанавливает cookie и возвращает `{user}`. |
| `POST /auth/resend` | `{challengeId}`. Возвращает новый вызов подтверждения. |
| `GET /auth/me` | `{user}` с профилем и признаком обязательной смены пароля. Без сессии возвращает `{user:null}`. |
| `POST /auth/logout` | Завершает текущую сессию. |
| `PATCH /auth/profile` | `displayName`, `city`, `country`, `telegram`, `companyName` для компании. |
| `POST /auth/password` | `{currentPassword, newPassword}`. |
| `PATCH /auth/credentials` | `{currentPassword, newPassword, username?}` для администратора. |

Вызов подтверждения содержит `challengeId`, `expiresIn` в секундах и маскированный `email`. Роли при регистрации имеют значения `BUYER` и `SELLER`, типы участника — `COMPANY` и `INDIVIDUAL`. Статус ответа перед вводом кода не раскрывает, зарегистрирован ли этот email.

### Каталог и объявления

| Метод и путь | Назначение |
| --- | --- |
| `GET /categories`, `GET /locales`, `GET /content` | Категории, действующие словари и страницы. |
| `GET /listings` | Страница поиска `{items, total, page, limit, locked}`. Гость получает пустой список и `locked: true`. |
| `GET /listings/mine` | Собственные объявления. |
| `GET /listings/:id` | Карточка с проверкой доступа. |
| `GET /listings/:listingId/images/:imageId` | Обработанный WebP с проверкой доступа к карточке. |
| `POST /listings`, `PATCH /listings/:id` | Создание и изменение объявления. |
| `DELETE /listings/:id`, `POST /listings/:id/restore` | Архивирование и восстановление. |

Поиск принимает `q`, пагинацию `page` и `limit` и сортировку `sort`. При `q` по умолчанию используется релевантность, без текста — новизна. Допустимы `relevance`, `newest`, `price-asc` и `price-desc`. Фильтр `category` принимает код и включает подкатегории. Другие фильтры включают `kind`, `ownerType`, `availability`, `condition`, `originScope`, `priceMode`, `vat`, `counterparty`, `originCountry`, `destinationCountry`, `ownerCountry`, `city`, `paymentMethod`, `deliveryIncluded`, `customsIncluded`, `priceMin`, `priceMax` и `currency`. При ценовом диапазоне без валюты используется RUB. Псевдоним фильтра `originCountry` — `country`.

Для создания объявления передайте `categoryId`, `title`, `description` и параметры направления. Роль задаёт `kind` (`SELL` или `BUY`). Для покупателя нужны `destinationCountry`, `deliveryBy` и `originScope`. Для `COUNTRY` передайте `originCountry`, для `DOMESTIC` он совпадает со страной получения. Продавцу нужны `availability` и география отгрузки. Для склада требуется `stockCity`.

Для конкретного пункта отправления укажите `originScope: "COUNTRY"` и двухбуквенный код `originCountry`. Для гибкой отгрузки передайте `originScope: "ANY"` и `originCountry: null`. Старое тело с конкретным кодом без `originScope` остаётся допустимым. Частичное обновление без двух полей сохраняет прежнюю географию. Фильтр конкретной страны включает гибкие заявки и предложения. `originCountry=ANY` выбирает только записи с гибкой географией. В `deliveryBy` покупатель передаёт крайний срок поставки, продавец может передать последний день публикации предложения. Цена хранится до сотых, договорная цена передаётся как `null`.

### Загрузка фотографий

Для новых файлов отправляйте `multipart/form-data` на `POST /listings`, `PATCH /listings/:id` или `PATCH /admin/listings/:id`. Поле `data` содержит JSON объявления до 64 КиБ. Каждый новый файл передаётся частью `images`. В `data.imageOrder` укажите будущий порядок, используя UUID сохранённых фото и объекты с индексом нового файла с нуля.

```json
{
  "imageOrder": [
    { "fileIndex": 0 },
    "c1402d63-9317-4f35-9d28-562ee554f793"
  ]
}
```

Первая позиция задаёт обложку. Пустой массив удаляет все фото. Обновление полей без `imageOrder` сохраняет фотографии. Для перестановки и удаления без новых файлов достаточно JSON. Некорректный файл или ссылка на чужое фото приводит к отклонению всего изменения. Превышение размера возвращает `413`, занятый обработчик может вернуть `503`. Поле карточки `images` возвращает упорядоченные `{id, url, width, height}`.

### Администрирование

Рабочие маршруты модерации доступны сотрудникам с ролями `ADMIN` и `MODERATOR` после подтверждения почты и смены временного пароля. Страницы профилей, объявлений, жалоб, отзывов и действий доступны через `GET /admin/users`, `/admin/listings`, `/admin/reports`, `/admin/reviews`, `/admin/audit`. Поиск по объявлениям в админке также учитывает публичное имя автора. Справочники доступны через `GET /admin/categories`, `/admin/content`, `/admin/locales`.

Журнал фиксирует вход и выход сотрудников, смену реквизитов, создание модераторов, редактирование и смену статусов. Просмотр контактных данных профиля, списка с такими контактами, жалоб и переписки по жалобе тоже создаёт запись. Новая запись сотрудника содержит его логин на момент действия, постоянный `actorUserId` и `actorRole`. У автоматизации роль `AGENT`, а идентификатор сотрудника равен `null`. Сведения в исторической записи зависят от версии, на которой она появилась. Пароли и почтовые коды в журнале отсутствуют. [OWASP Logging](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html)

| Метод и путь | Назначение |
| --- | --- |
| `POST /admin/moderators` | Создание модератора из сессии администратора. Тело `{username, displayName, email, temporaryPassword}`. |
| `GET /admin/users/:id` | Профиль по точному идентификатору. Модератор видит контакты покупателей и продавцов. |
| `PATCH /admin/users/:id` | Редактирование профиля. |
| `GET /admin/listings/:id`, `PATCH /admin/listings/:id` | Чтение и правка объявления. |
| `GET /admin/reviews/:id`, `GET /admin/reports/:id` | Отзыв или жалоба по точному идентификатору. Списки `/admin/reviews` и `/admin/reports` поддерживают `subjectId`. |
| `GET /admin/reports/:id/messages` | Переписка по жалобе с пагинацией и аудитом доступа. |
| `PATCH /admin/:entity/:id/status` | Изменение статуса профиля, объявления, отзыва или жалобы. Тело `{status, reason}`. |
| `POST /admin/categories`, `PATCH /admin/categories/:id` | Создание и обновление категории. |
| `PUT /admin/content/:key`, `PUT /admin/locales/:code` | Запись страницы или локали. |
| `GET /admin/audit?actorRole=MODERATOR` | Журнал с фильтром по роли `ADMIN`, `MODERATOR` или `AGENT`. |

Для CLI и MCP есть выделенный HTTP-маршрут модерации `users` и `listings`. Установите `MODERATION_AGENT_TOKEN` длиной от 32 символов и передавайте его только интеграции. Для новой операции укажите уникальный `Idempotency-Key` длиной 8–128 символов из латинских букв, цифр, точки, дефиса или подчёркивания.

```sh
curl --fail-with-body --request PATCH \
  --url "$APP_ORIGIN/api/v1/agent/moderation/listings/$LISTING_ID" \
  --header "Authorization: Bearer $MODERATION_AGENT_TOKEN" \
  --header "Idempotency-Key: $MODERATION_OPERATION_ID" \
  --header 'Content-Type: application/json' \
  --data '{"status":"FROZEN","reason":"Проверка полученной жалобы"}'
```

Доступны `FROZEN`, `ACTIVE` и `BANNED`. Повтор сетевого запроса с прежним ключом и данными возвращает `replayed: true`. Изменение тела под прежним ключом возвращает `409`. Действия проходят через журнал модерации.

## Тестирование

Запускайте проверки на одноразовых базах с вымышленными аккаунтами и объявлениями. Проверки авторизации, админки и фотографий меняют реквизиты тестового администратора. Для таких прогонов выделяйте отдельные проекты Compose и порты.
