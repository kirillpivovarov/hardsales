# hwforai · закрытая биржа

Площадка для закупки и продажи серверного оборудования. Покупатели публикуют заявки, поставщики размещают предложения. Каталог и автоматические совпадения помогают найти встречное объявление. Переговоры начинаются в чате. Стороны решают, когда открыть контакт Telegram.

Эта версия находится в ветке `maxv`. Для её локальной проверки используется отдельный проект Docker Compose.

## Локальный запуск

Откройте Docker Desktop или запустите Docker Engine с Compose. Скачайте отдельный клон.

```sh
git clone --branch maxv --single-branch https://github.com/kirillpivovarov/hardsales.git "$HOME/hardsales-maxv"
cd "$HOME/hardsales-maxv"
EXCHANGE_DEMO_FEATURES=true sh scripts/update-maxv.sh
```

- [Сайт на порту 3100](http://127.0.0.1:3100)
- [Тестовая почта Mailpit на порту 8125](http://127.0.0.1:8125)

`EXCHANGE_DEMO_FEATURES=true` подготавливает демонстрационные данные и включает режим приглашений, проверки и совпадения. Сетевой импорт справочника включается отдельно. Логины, пароли, почта и приглашения перечислены в [руководстве пользователя](docs/USER_GUIDE.md).

## Обновление Docker Desktop на macOS

Выполните в Terminal при запущенном Docker Desktop.

```sh
cd "$HOME/hardsales-maxv" &&
EXCHANGE_DEMO_FEATURES=true sh scripts/update-maxv.sh
```

Скрипт проверяет ветку, адрес репозитория и локальные правки. Он обновляет проект `hwforai-maxv` и ждёт готовности приложения. База хранится в томе `hwforai-maxv_postgres-data`. Для диагностики используйте `docker compose ps` и `docker compose logs --tail 100 app`. [Резервная копия демостенда](docs/operations.md#резервная-копия-и-восстановление)

## Работа с площадкой

- **Поиск** начинается на главной «Железо для ИИ». Выберите категорию или введите название оборудования. В каталоге уточните выдачу фильтрами. На телефоне откройте панель кнопкой «Фильтры».
- **Участники** подтверждают почту, публикуют объявления и ведут переговоры. Совпадения учитывают модель, количество, цену, доставку и оплату. Проверка документов и история сделок отражаются в профиле.
- **Модераторы и администратор** открывают действия по конкретному объявлению или его автору в карточке объявления. Категории, страницы и языки редактируются в соответствующих разделах администрирования. В каталоге у сотрудников есть одна ссылка **«Управление категориями»**.
- **Администратор** также ведёт приглашения, права модераторов, курсы валют и настройки биржи. Действия с данными фиксируются в журнале.

API и интерфейс работают с одного origin. Маршруты API начинаются с `/api/v1`, готовность приложения проверяется через `GET /api/v1/health`. Сервер проверяет контрольные суммы старых миграций и применяет новые при запуске. PostgreSQL хранит объявления, фотографии, документы, чаты и журнал аудита.

## Разработка и тестирование

Нужны Node.js 22.12+, npm и PostgreSQL 17. Используйте отдельную базу и переменные из [.env.example](.env.example).

```sh
npm --prefix server ci
npm --prefix web ci
npm run check
npm run build
```

Для редактирования интерфейса запустите `npm --prefix web run dev`. Vite передаёт запросы к API на порт 3001. На готовой локальной сборке `npm run dev` запускает API и отдаёт статический клиент. Проверки функций запускайте по [чек-листу](docs/QA_CHECKLIST.md) и [инструкциям](docs/qa.md).

Для рабочего развёртывания используйте выделенный VPS, проверенный коммит `maxv`, отдельную базу, HTTPS и SMTP. Порядок настройки, обновления и отката собран в [руководстве администратора](docs/ADMIN_VPS.md).
